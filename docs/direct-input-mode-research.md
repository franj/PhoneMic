# 直接输入模式（动态文字上屏）调研总结

> 调研日期：2026-08-25  
> 状态：已搁置，悬浮窗模式够用。本文件供日后重启时参考。

## 背景

当前 PhoneMic 的文字输入流程：

1. 手机端每次输入都发 `preview` 事件，电脑端只在**悬浮窗**里显示文字
2. 语音识别结束、手机发 `send` 事件时，通过**剪贴板粘贴**（Ctrl+V）一次性上屏

**设想的新模式**：preview 阶段的文字直接打进目标输入框，识别过程中动态更新——像输入法一样逐字出现在光标位置。与悬浮窗模式二选一，用户自选。

## 方案评估

### 方案 A：键盘模拟 + diff 计算（已采纳，后搁置）

**原理**：用 `SendInput` 模拟键盘逐字打字，文字变化时做 diff（找公共前缀，只删差异部分、只打新增部分），send 时删掉所有 preview 文字再一次性粘贴最终结果。

**优点**：
- 不需要注入目标程序，不触发杀毒
- 不区分输入框类型（`SendInput` 是 OS 层面键盘模拟，对所有控件通用）
- 最终粘贴是原子操作，Ctrl+Z 一次撤销整段

**缺点**：
- send 时有"删-贴"的瞬间闪烁（<50ms，基本无感但理论存在）
- preview 期间用户不能切窗口/输入框，否则文字打错位置
- 需要检测焦点变化来回退

### 方案 B：剪贴板方式做 preview 更新（未采用）

每次 preview 更新 = 选中上一次打的字 + 粘贴新内容。每次更新是原子的，撤销干净。但精确选中"自己打的字"不碰用户原有文字很难，且自绘控件对 Shift+方向键选区行为不一致。复杂度高，放弃。

### 方案 C：TSF 输入法（理想方案，不合适）

**原理**：注册成 Windows TSF Text Service Provider（输入法），用 composition 机制管理动态文字，提交时原子化，撤销完美。

**结论：技术上完美，但产品上不合适。**

- TSF 的 composition 机制只有被系统激活的输入法才能用，普通程序无法操作
- 注册成输入法 = COM DLL 被系统加载进目标进程（系统官方注入，不会被判病毒）
- **但用户体验变了**：用户需要 Win+Space 切到 PhoneMic 输入法，用完切回去；切过去后电脑键盘也被 PhoneMic IME 拦截，不能互不干扰
- 跟产品"扫码即用、轻量无感"的定位矛盾

## 方案 A 技术细节（日后重启用）

### 状态机

```
IDLE → TYPING → (preview变化) → UPDATING → (send) → COMMITTING → IDLE
                   ↑___________|
                每次文字变化都回到这里

异常：焦点丢失/用户手动操作 → 回退 HUD 模式
```

### 核心状态

- `typed_text`：当前已打进目标输入框的文字
- `preview_window`：preview 开始时记录的前台窗口句柄 + 焦点控件句柄

### Diff 算法

语音识别的文字变化通常是"往后追加"或"末尾修正"，公共前缀匹配足够：
- "你好" → "你好世界"：公共前缀"你好"，只需打"世界"（2字新增，0字删除）
- "你好世界" → "你好石阶"：公共前缀"你好"，删2字打2字

### SendInput 性能

| 操作 | 耗时 | 人能否感知 |
|------|------|-----------|
| 100次独立 SendInput 调用 | 约 10-50ms | 完全无感 |
| 1次 SendInput 批量发100个按键 | 约 1-5ms | 完全无感 |
| 对比：一次剪贴板粘贴 Ctrl+V | 约 5-20ms | 无感 |

- 100次退格比一次粘贴还快，人眼感知门槛 100ms
- SendInput 事件进 Windows 输入队列，不会丢，最多排队延迟
- 语音输入一句话通常 10-50 字，极端 100-200 字，都在毫秒级

### 焦点检测

分层策略：

1. **窗口变了** → 一定回退（`win32gui.GetForegroundWindow()`，项目已用）
2. **控件变了** → 一定回退（`win32gui.GetGUIThreadInfo` 的 `hwndFocus`）
3. **光标在同一控件内移动** → 尽量检测（`rcCaret` 坐标），检测到就回退，检测不到就随它去

前两点能挡住绝大多数情况，第三点不是每个应用都靠谱。

### 悬浮窗模式 vs 直接输入模式对比

| | 悬浮窗模式（现在） | 直接输入模式（新） |
|---|---|---|
| preview 阶段 | 文字只在悬浮窗显示 | 文字直接打进输入框 |
| 能不能中途切窗口 | 能 | 不能 |
| 视觉效果 | 悬浮窗预览 | 输入框逐字出现，像输入法 |
| 撤销 | 一次粘贴，Ctrl+Z 一步 | 删-贴，Ctrl+Z 一步 |
| 适合场景 | 多窗口切换、不确定打哪 | 目标明确、想要沉浸感 |
| 复杂度 | 低（已实现） | 中（状态机+diff+焦点检测） |

## 结论

悬浮窗"不挑输入框、不挑窗口、不怕光标乱跑"，简单可靠。直接输入模式虽然视觉效果好，但焦点检测和边界情况复杂，收益不大。搁置。
